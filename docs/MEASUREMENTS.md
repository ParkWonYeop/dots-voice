# 기존 측정과 검증 범위

2026-09-30, M5 / 메모리 32GB / macOS / Chrome에서 기록한 결과다. 공개 릴리즈의 모든 사용자 환경에서 재현되는 성능 보장은 아니다.

## Mac 합성 비교

같은 한국어 테스트 문장을 실제 브라우저의 로컬 재생 연결로 보냈다.

| 설정 | 음성 길이 | 합성 시간 | 첫 PCM 청크 | 합성 시간 / 음성 길이 |
| --- | --- | --- | --- | --- |
| 이전 VoiceDesign 1.7B · 640ms 청크 | 11.76초 | 8.28초 | 617ms | 0.704 |
| 고정 참조 Base 0.6B · 320ms 청크, 무음 보정 전 | 10.64초 | 6.14초 | 236ms | 0.577 |

첫 PCM은 모델 합성 시작 기준이다. 사용자가 말을 마친 뒤 듣기까지의 전체 지연과 다르다. 말속도와 생성 음성 길이도 달라졌으므로 합성 시간만으로 속도 향상률을 계산하지 않는다. 새 통화 인사에서는 첫 자막→합성 요청 약 193ms, 요청→첫 PCM 약 232ms를 관측했다.

## 음색·휴지·중단

세 문장의 화자 임베딩 평균 코사인 유사도는 이전 VoiceDesign 0.9698, 고정 참조 방식 0.9891이었다. 제한된 비교 지표이며 자연스러움이나 동일 음색을 보장하지 않는다. 로컬 ASR 비교에서는 문장이 대체로 유지됐지만 일부 어미와 `네/내` 판별 차이가 있었다.

반복 패널티를 1.2로 조정하고 RMS 0.002 미만의 긴 무음을 목표 240ms로 줄이되, 재생 여유가 부족하면 삭제량을 제한했다. 원래 약 2.02초였던 한 예제의 쉼은 실제 통화 출력에서 약 480ms였다. 해당 구간은 첫 PCM 368ms, 음성 4.96초, 합성 5.01초였고 버퍼 고갈 증가분은 0이었다. 앞선 통화 시작 구간에는 6회 고갈이 있어 전체 통화가 끊김 없다고 평가하지 않는다.

`underflows`는 합성이 진행 중인데 재생할 PCM이 고갈된 횟수다. 자막 도착을 기다리는 시간이나 생성 음성 안의 무음은 포함하지 않는다. 사용자 발화 중단은 입력 자막 도착 후 처리되므로 마이크 발화 시작과 정확히 일치하지 않는다.

## 공개 릴리즈에서 확인하는 것

- 모델 없는 Python·JavaScript 검사, Mac 네이티브 호스트 실행, 모의 Windows 등록·장치 선택·취소 경로.
- 두 ZIP의 체크섬, 참조 WAV, 플랫폼 설정, macOS 실행 권한, Windows 줄바꿈, 추출한 패키지의 네이티브 ping.
- 실제 통화 전체 경로는 설치할 컴퓨터의 Chrome에서 확인해야 한다.
- Windows 실기기 CUDA/CPU 합성·Chrome 통화, 장시간 안정성, 다른 Mac 사양은 미검증이다. Windows 설치기는 해당 PC에서 합성 시간을 측정한다.

기존 비교 WAV·통화 진단 출력은 공개 소스나 설치 ZIP에 포함하지 않는다. 배포에는 선택한 합성 참조 WAV 하나만 포함한다.
